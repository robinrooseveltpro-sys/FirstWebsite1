How to encode and decode HTML entities

HTML character references represent characters using named or numeric sequences. They are particularly useful for representing reserved HTML syntax characters, displaying code samples, and preserving text where literal characters might be interpreted as markup.

Which HTML characters should be encoded?

In HTML text, the ampersand and less-than sign are especially important because they participate in HTML parsing. Greater-than signs and quotation marks are commonly escaped too, particularly when preparing snippets for reuse. 

Original:

Tom & Jerry


Encoded:
<p>Tom & Jerry</p>

Decoded:

Tom & Jerry

In a quoted HTML attribute, the quote character that surrounds the attribute value needs proper escaping. The safest approach depends on where and how the value will be inserted.

Named vs. decimal vs. hexadecimal entities

Named HTML entities

Named references use a name between an ampersand and a semicolon. For example, &copy; represents © and &euro; represents €. They are usually easier for people to recognize, but not every Unicode character has a named entity.

Decimal numeric references

Decimal references represent a Unicode code point using a base-ten number. For example, &#169; represents ©. This tool's decimal mode encodes every code point in the input.

Hexadecimal numeric references

Hexadecimal references use a number in base sixteen, usually introduced by &#x. For example, &#xA9; represents ©. Hexadecimal references can be convenient when working with Unicode code points.

Non-ASCII characters and emoji

Modern HTML documents can contain Unicode text directly when the document's character encoding is configured correctly. Numeric references can still be useful when a workflow specifically requires encoded output. This tool iterates Unicode code points, so characters represented by surrogate pairs, such as many emoji, are not incorrectly split into separate entities.

Does HTML entity encoding prevent XSS?

Encoding important HTML characters can help prevent text from being interpreted as markup in the appropriate HTML text context. However, this utility is not an HTML sanitizer, security scanner, or universal XSS protection system.

Different contexts require different handling. HTML text, quoted attributes, URLs, JavaScript, and CSS each have distinct parsing rules. Do not assume that encoded output is automatically safe to insert into every context, and do not treat decoding as sanitization. Use context-appropriate escaping and established security practices in production applications.

What this tool does not do

  • It does not sanitize arbitrary HTML or guarantee protection from cross-site scripting vulnerabilities.
  • It does not validate an HTML document's complete structure or repair broken tags.
  • It does not convert HTML tags into plain text automatically. Encoding markup turns its syntax characters into references so the markup can be displayed as text.
  • Its named-entity encoding mode uses a curated set of common mappings. Decoding supports the named character references recognized by the browser's HTML parser.

Frequently asked questions

What is an HTML entity encoder?

An HTML entity encoder converts selected characters into character references such as &lt;, &gt;, and &amp;. These references allow reserved characters to be represented in an HTML document without using their literal parsing significance in the same way.

How do I decode HTML entities into normal text?

Select Decode HTML entities, paste the encoded string, and run the conversion. The tool decodes supported named, decimal, and hexadecimal references, then displays the result as plain text.

What is the difference between &lt; and &#60;?

Both represent the less-than character. &lt; is a named reference, while &#60; is a decimal numeric reference. A hexadecimal form is &#x3C;.

Can I encode emoji and Unicode characters?

Yes. Enable the non-ASCII option to convert characters without a mapped named entity into decimal references, or choose a numeric mode to encode every character. Emoji are handled by Unicode code point.

Can I encode HTML tags so they display as text?

Yes. For example, an opening less-than sign becomes &lt; and a closing greater-than sign becomes &gt;. This lets an HTML code sample be displayed as text rather than used as the actual element markup.

Is this HTML entity encoder and decoder free?

Yes. The conversion, copy, and download features on this page are available without an account or a tool usage fee.

Does this tool upload my text?

No. The conversion runs in your browser, and selected files are read locally. The text you enter is not uploaded to our server by this tool.

Does decoding HTML entities make HTML safe?

No. Decoding turns references back into their corresponding characters, which may include markup syntax. The resulting text is not sanitized. Keep it in a text field when you only need to inspect it, and use appropriate security practices before inserting untrusted data into a webpage.

Why is my encoded output longer than the original?

An entity uses several characters to represent one original character. For instance, a less-than sign becomes &lt;. Numeric modes may make the output much longer because every input code point is replaced with a numeric reference.

What if I decode an already decoded string?

The default mode decodes once to avoid unexpectedly transforming nested references multiple times. Repeated decoding can be enabled when you specifically need it, but always check the result before using it in another application.
