What an MP3 tag editor actually changes

An MP3 file is two things stacked together: the audio frames, which contain the compressed sound, and the ID3 tag, which is a block of metadata attached to the start of the file. The tag holds the title, artist, album, year, cover art, and dozens of other fields that music players and phone libraries read to organise your music.

Editing a tag does not touch the audio. It rewrites the metadata block and leaves the sound data exactly where it was. That is why this tool can promise no quality loss — it never re-encodes anything.

ID3v1, ID3v2.2, ID3v2.3, ID3v2.4

There are several incompatible versions of the ID3 standard. The important ones:

VersionSizeNotes
ID3v1128 bytes, end of fileAncient. 30-character fields, no cover art, no Unicode. Many players still read it as a fallback.
ID3v2.2Start of file3-character frame IDs. Obsolete; rarely produced today.
ID3v2.3Start of fileWhat this tool writes. Universally supported, including cover art and Unicode.
ID3v2.4Start of fileNewer, UTF-8 throughout, but a few older players and car stereos mishandle it.

This tool writes ID3v2.3 deliberately. It is the most compatible target: Windows, macOS, Android, iOS, and most car head units read it correctly. Writing ID3v2.4 would be technically newer but would break playback information in a small but real number of older devices.

Cover art adds to the file size

Artwork is embedded inside the MP3. A 2 MB JPEG cover makes the file 2 MB larger — which matters if you are editing a whole album of 3 MB tracks. The practical rule: keep covers at 1000×1000 pixels, JPEG, under 500 KB. That looks sharp on every player and adds a fraction of a megabyte.

This tool accepts JPEG and PNG. PNG is technically fine but typically 3–5× larger than JPEG at the same dimensions for photographic artwork, so JPEG is the better choice unless the cover has hard edges and flat colours.

Why a browser tool rather than desktop software

The reference desktop tool, Mp3tag, is excellent and free — but it requires installation, and it is Windows-only (with a macOS alternative that is separate software). For a quick fix on a borrowed machine, a Chromebook, or a phone, a browser tool is the practical choice. The trade-off is that a browser tool cannot reach across folders the way desktop software can: you add files explicitly, and you download the results.

Tagging basics

How do I edit MP3 tags online?

Drop an MP3 onto the upload area, click it in the file list, and the tag form fills with its current values. Change any field, then press Download tagged MP3. The file is rewritten in your browser with the new ID3v2.3 tag block and downloaded — the original on your disk is untouched, so you keep a backup automatically.

Does editing tags reduce audio quality?

No. The audio frames are copied unchanged; only the ID3 metadata block is rewritten. There is no re-encoding, no resampling, and no generation loss. The sound in the output is bit-identical to the sound in the input.

Which tag fields can I edit here?

Title, artist(s), album, album artist, year, track number, disc number, genre, composer, publisher, copyright, and embedded cover art. That covers the fields that music players and phone libraries actually read. Non-standard fields such as lyrics, ReplayGain, and MusicBrainz IDs are not editable and are not preserved.

What is the difference between "Artist" and "Album artist"?

Artist is who performed the track. Album artist is who the album is credited to. On a collaboration album, each track might list different artists, while the album artist stays constant — that field is what groups the album correctly in most players. For a single-artist album, set both to the same value.

How do I enter multiple artists?

Separate them with a slash in the Artist field: Eminem / 50 Cent. The tool splits on slashes and writes each as a separate ID3v2.3 value, which is how players display multiple performers. Commas are not split, because many single artist names contain them — “Earth, Wind & Fire” is one artist, not three.

Cover art

How do I add cover art to an MP3?

Select a file, then press Choose image under the cover art section and pick a JPEG or PNG. A preview appears. Press Download tagged MP3 and the artwork is embedded in the ID3 tag as an APIC frame — the standard field every player reads for album artwork.

Why is my cover art not showing in my music player?

Three common causes. First, the player may be reading a cached thumbnail — try removing and re-adding the file to its library. Second, the image may be embedded but in an unsupported format; JPEG is the safest. Third, the file may have a second ID3 tag (ID3v1 at the end of the file) that takes precedence in older players. This tool removes all existing tags before writing, which eliminates the third cause.

What size should album art be?

1000×1000 pixels, JPEG, under about 500 KB. That is sharp on phones, desktop players, and most car displays, while adding only half a megabyte to each file. Embedding a 3000×3000 PNG can add several megabytes per track, which is painful across a full album.

Why does adding cover art make my MP3 bigger?

Because the image bytes are stored inside the file as part of the ID3 tag. A 400 KB cover makes the MP3 400 KB larger — there is no way around that. If file size matters, shrink the cover before embedding rather than after.

Can I remove existing cover art?

Yes. Select the file and press Remove cover, then download. Because the tool rewrites the entire tag block, the APIC frame is simply not written, and the artwork is gone from the output file.

Batch editing

Can I edit tags on multiple MP3 files at once?

Yes. Add several files at once — the queue on the left lists them all. Edit each one individually by clicking it, or use Apply album info to all to copy the album, album artist, year, genre, and cover art from the current file to every other file in the queue. Track number and title stay per-file, which is correct: those are per-track fields.

Why does the tool download files one at a time?

Because browsers deliberately block multiple automatic downloads from a single click — it is an anti-abuse measure you cannot bypass. Save all edited processes every file and turns each row in the queue into a download button, so you click each one. It is one extra click per file, and it is the only approach that works reliably across Chrome, Firefox, and Safari.

Is there a file count or size limit?

No hard limit, but there is a memory one. Each queued file is held in memory while you edit, so 30 files at 10 MB each would use 300 MB. In practice, batches of 10–20 typical tracks work fine on any modern machine. Very large single files (over 50 MB) work but are slow to read.

What happens to my original files?

Nothing. The tool reads a copy into memory and gives you a new downloaded file. Your original files on disk are never modified. That means an accidental mistake costs you nothing — just do not delete the originals until you have checked the output.

Music library

Why are my MP3 tags wrong or missing?

The usual causes are ripping software that wrote ID3v1 only (30-character truncation, no Unicode), downloads from sources that shipped blank tags, or files edited by several tools over the years leaving conflicting tag versions. This tool reads what is present, shows it, and writes a single clean ID3v2.3 block — which resolves the conflicting-versions case entirely.

Why does my phone show different tags than my computer?

Because the two are reading different tag versions. Many phones prioritise ID3v2.3, while older desktop players may fall back to ID3v1. A file with both can show correct information in one place and stale information in another. Rewriting the tag here removes all versions and writes only ID3v2.3, so every device reads the same data.

Should genre be a standard value or free text?

Free text is fine and is what ID3v2.3 expects — unlike ID3v1, which used a numeric genre table. Common values like Rock, Hip-Hop, Jazz, and Podcast sort predictably in most players. Very unusual values work, but some players group unlisted genres into an “Other” bucket.

What is the correct track number format?

5 for a single number, or 5/12 for track 5 of 12. The total is optional but helps players display “5 of 12” and calculate remaining time. Same format for disc numbers: 1 or 1/2.

Podcasts & audiobooks

Can I use this to tag podcast episodes?

Yes. Podcast MP3s are ordinary MP3 files with ID3 tags. Put the episode title in Title, the show name in Album, and the host or network in Artist. Set genre to Podcast, and add the show artwork as cover art. Note that podcast directories read tags from the RSS feed, not from the MP3 — the tag matters for local playback and for players that display embedded metadata.

How do I tag M4B audiobooks?

This tool reads tags from M4B, M4A, FLAC, and OGG files, but it can only write ID3 tags to MP3. For M4B you need a tool that writes MP4 atoms rather than ID3 frames — a different format entirely. The reader here will still show you the current title, author, and album, which is useful for checking what is already there.

Where do I put the narrator name?

ID3v2.3 has no dedicated narrator frame. The conventional place is the Composer field — many audiobook players read it that way — or the Artist field alongside the author. There is no universally correct answer, so pick one and be consistent across the series.

Privacy & technical

Is my MP3 uploaded to a server?

No. Tag reading uses jsmediatags and tag writing uses browser-id3-writer, both running in your browser tab. The file is read with the File API, processed in memory, and offered back as a download. Nothing is transmitted. You can verify this in your browser's network tab — the only requests are for the two libraries themselves, not your audio.

Does it work offline?

After the libraries have loaded once, yes. Both are cached by the browser, and all processing is local. You can disconnect from the network and continue editing files in the same session.

Why does the page load a library instead of bundling it?

Because a static HTML page cannot bundle an ES module without a build step. jsmediatags is loaded as a classic script and browser-id3-writer as an ES module from a CDN, both lazily on first use rather than on page load, so the page itself stays fast. If you need a fully self-hosted version, both libraries can be downloaded and served from your own domain.

Which tag fields are lost when I save?

browser-id3-writer removes all existing ID3 tags before writing the new ones. Standard fields are preserved because the tool reads them and prefills the form. Non-standard fields are not preserved: unsynchronised lyrics (USLT), ReplayGain, MusicBrainz identifiers, custom TXXX frames, and chapter markers. If your files carry those and you need them, keep the original.

Is there a watermark, file limit, or subscription?

No watermark, no signup, no daily limit, no subscription. The downloaded MP3 is a normal MP3 with no added branding. The tool is free to use and runs entirely on your own machine.
