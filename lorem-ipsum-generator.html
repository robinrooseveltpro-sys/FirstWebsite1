Why bother with a count field

  
Most lorem ipsum generators hand you a paragraph and let you deal with the leftovers. That works fine when you are filling a blog body. It falls apart the moment a real container has a real limit.

  
A product card title has about 60 characters before it wraps. A meta description gets truncated around 155. A testimonial slot in a pricing table holds 28 words at best. If you paste three paragraphs into any of those and start deleting word by word, you have turned a two-second task into a five-minute one. Picking the count first is faster and it keeps the sentence structure intact, so the mockup actually shows what the real content will look like.

  
Character mode trims at a word boundary rather than cutting mid-word, which matters if you are testing truncation behaviour. Word mode gives you a clean token count with proper punctuation. Paragraph mode is the one you want for a CMS body field. Sentence mode is for captions, tooltips and alt text.


  
What the seed actually does

  
The generator runs a small seeded pseudo-random function — mulberry32 — rather than Math.random(). Your seed string is hashed into a 32-bit integer, and that integer drives every word choice. The practical effect: layout-test-01 plus 120 words plus the Tech theme will produce byte-identical output today, tomorrow, and on a colleague's machine.

  
This sounds like a small thing until you have three people reviewing the same Figma file. Without a seed, every refresh reshuffles the text and the line breaks move, so a comment like "the third line wraps awkwardly" stops making sense an hour later. With a seed, the text is fixed and the conversation stays anchored to what everyone is actually looking at.

  
Change the seed and you get a completely different document. Hit Shuffle for a random one, or type something memorable like client-review-v3 so you can find it again.

JSX wraps the paragraphs in a fragment with keys, which is the form you want when you are building a component skeleton in React. JSON gives you an array of strings, ready for a fixture file or a mock API response.

Basics


    

      
What is lorem ipsum, exactly?

      
It is scrambled Latin. The text descends from Cicero's De Finibus Bonorum et Malorum, written around 45 BC, but the words have been shuffled and truncated so the result reads as Latin without forming coherent sentences. That is the point — it looks like language at a glance, so you judge the layout instead of reading the words.

    


    

      
Why not just type "text text text"?

      
Because repeated short words produce an unrealistic line rhythm. Real English has a mix of two-letter and twelve-letter words, and that mix is what determines how a column of text actually breaks. Lorem ipsum preserves a natural distribution of word lengths, so your line counts and widow/orphan behaviour match what real copy will do.

    


    

      
Is any of this real Latin?

      
Individual words are real. The sentences are not. The classic pool draws from genuine Latin vocabulary, but the grammar is deliberately broken so no reader mistakes it for meaningful text. The Hipster, Tech, Pirate and Legal themes are English word pools styled to match their subject, not Latin at all.

    

  


  

    
Counts & limits


    

      
How do I get exactly 150 characters?

      
Switch Count by to Characters and enter 150. The generator builds words until it passes the target, then trims back to the last word boundary at or under 150. You get a clean ending rather than a chopped word, and the character count in the stats bar confirms the result.

    


    

      
What's a sensible word count for a product card?

      
Usually 20 to 30 words for a description block, and 6 to 10 for a card title. If the card has a fixed height, generate at the upper end — a card that survives 30 words will survive 18, but not the reverse.

    


    

      
Why does my meta description get cut off at 155 characters?

      
Google truncates around that point on desktop. Generate at 150 characters to test it safely. The character count in this tool includes spaces and punctuation, which matches how search engines and most CMS fields count.

    


    

      
Does the character count include spaces?

      
Yes. The stat reflects the full string length, spaces and punctuation included, because that is how HTML fields, database columns and search snippets measure it.

    

  


  

    
Seeds


    

      
How does the seed make the output repeatable?

      
Your seed string is hashed into a number, and that number initialises a deterministic random function. Every word pick draws from that function in the same order, so the same seed with the same mode, amount and theme always produces the same text. Nothing about it depends on the clock or the machine.

    


    

      
If I change the amount, does the text change?

      
The beginning stays the same and the text extends or truncates. That is intentional — you can bump a mockup from 80 words to 120 words and the first 80 remain identical, so line breaks early in the block do not shift.

    


    

      
Can two different seeds produce the same text?

      
In theory a hash collision is possible. In practice, with a 32-bit space and short documents, you would need to try millions of seeds to find one. It is not a concern for design work.

    

  


  

    
Export


    

      
Which tag should I pick for HTML output?

      
p for body copy, div when the container has its own class and you do not want default margins, span for inline placeholders inside a heading or button, and li when you are filling a list skeleton.

    


    

      
What does the JSX output look like?

      
Each paragraph becomes a self-contained element with a numeric key, wrapped in a fragment. It is meant to be pasted directly into a component file while you are building out a page, then replaced with a data source later.

    


    

      
Why is the JSON an array of strings?

      
Because that is the most common shape for fixture data. You can drop it into a mock server response, a Storybook story, or a test file without reshaping it. Each element is one paragraph.

    


    

      
Does Copy match what I see in the Code tab?

      
Yes, exactly. The Code tab renders the same string the clipboard receives, including the tag wrapping and line breaks.

    

  


  

    
Themes


    

      
When should I use something other than Classic?

      
Use Cicero when you need longer clauses to test reading rhythm. Use Tech for developer documentation. Use Hipster when a screenshot needs visual energy. Legal is the one to reach for when testing a long clause box or terms panel. Classic remains the safest choice for anything a client will see.

    


    

      
Can I mix themes?

      
Not in one run. Generate separately and combine if you need it — though mixed-language placeholder text usually makes a mockup harder to review, not easier.

    

  


  

    
Practical use


    

      
Does this work for Figma and Sketch?

      
Copy as plain text and paste directly into a text layer. Both tools preserve the line breaks between paragraphs. If your design system uses auto-layout with a fixed height, generate at the longest count you expect so the frame does not overflow in review.

    


    

      
Is placeholder text bad for accessibility?

      
Only if it ships. Screen readers will attempt to pronounce Latin, and the result is confusing. Keep lorem ipsum in mockups and staging environments, and make sure your build pipeline or content checklist replaces it before anything goes to production.

    


    

      
Does anything get sent to a server?

      
No. The generator, the seed hashing and the formatting all run in the page. There is no network request involved in producing or copying the text.
