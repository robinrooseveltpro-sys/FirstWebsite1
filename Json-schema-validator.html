What is JSON Schema validation?

JSON Schema is a way to describe the structure and constraints expected for JSON data. A schema can require properties, specify data types, limit numbers and string lengths, restrict allowed values, validate array items, and control whether unknown properties are permitted.

For example, a user schema might require a string name, a valid-looking email value, and an integer age above a minimum. Validation checks the JSON against those rules and reports where a mismatch occurs.

Common JSON Schema rules

  • type: specify string, number, integer, boolean, object, array or null.
  • required: identify object properties that must be present.
  • properties: define validation rules for named object fields.
  • additionalProperties: allow or reject fields not listed in the schema.
  • minimum / maximum: constrain numeric values.
  • minLength / maxLength: constrain string length.
  • pattern: match a string against a regular expression.
  • items: validate array elements against a schema.
  • enum / const: limit a value to an allowed list or a single value.

How to use the JSON Schema Validator

  1. Paste or load your JSON Schema.
  2. Paste or load the JSON document you want to validate.
  3. Select “Validate JSON.”
  4. Review the result and the data path, rule and explanation for each reported error.
  5. Edit the input and validate again, or download the report for debugging.

What does a data path mean?

Error paths use JSON Pointer-style paths. The path /user/email identifies the email property inside the user object. Array paths include an index, such as /items/2. An empty path indicates an issue associated with the document root or a whole-object rule.

Important limitations

This page targets JSON Schema Draft-07. Some newer keywords belong to later schema drafts and may not be interpreted as intended here. External $ref URLs are not automatically fetched, and unsupported custom formats are not guaranteed to receive format-specific validation.

A valid result means the data passed the rules recognized by this validator. It does not establish business correctness, verify external resources, authenticate data, or guarantee that a particular API accepts it.

The page processes inputs locally in your browser and does not send the JSON document to this website. The validator library is downloaded from a CDN. Use a trusted device and take care when working with sensitive information in browser tools.

Frequently asked questions

What is the difference between a JSON formatter and a JSON Schema validator?

A formatter improves the readability of valid JSON. A schema validator checks whether JSON data follows a set of defined requirements, such as required fields, data types and allowed values.

Can this tool check required fields and data types?

Yes. Draft-07 rules such as type, required, properties, enum, const, minimum, maximum, pattern, array item schemas and additionalProperties are supported by the validator.

Why does my JSON fail validation even though it is valid JSON?

JSON syntax and schema validation are different. Data can be valid JSON but fail a schema because a required property is missing, a value has the wrong type, or a constraint is not satisfied.

Does this page support every JSON Schema version?

No. This implementation targets Draft-07. Draft-2019-09, Draft 2020-12 and older draft-specific schemas may need another compatible validator configuration.

Are external $ref schemas downloaded?

No. The page does not fetch remote references. Local references to definitions contained in the schema can work, while unresolved external references will produce a compile error.

Are my JSON inputs uploaded?

No upload endpoint is implemented for the input. Parsing and validation run in your browser. The library code itself is loaded from a CDN.

Does a valid result guarantee correct business data?

No. Validation only checks the configured schema rules. It does not confirm that a customer exists, that a price is commercially correct, or that an application will accept the document for other reasons.
