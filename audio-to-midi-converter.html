How to turn audio into MIDI

Converting audio to MIDI means answering one question repeatedly: what pitch is sounding right now, and when does it change? The output is not a recording — it is a sequence of note events with a pitch and a duration, which is exactly what a MIDI file stores.

This tool handles the monophonic case: one melody at a time. That is the right scope for humming, whistling, singing a single line, or recording one instrument. Polyphonic transcription — separating a chord into its notes — is a much harder research problem, and the honest thing to say is that this tool does not do it.

Why YIN and not FFT

The most common way to analyse audio in the browser is an FFT, which converts a window of samples into a frequency spectrum. It is fast, but it has a resolution limit: at the usual Web Audio settings, each frequency bin is about 23 Hz wide. Two low notes that are only 5 Hz apart cannot be told apart.

YIN works in the time domain instead. It looks for the period at which the waveform repeats — the fundamental period — and with parabolic interpolation around that peak it gets sub-sample resolution. That is why it is the reference algorithm for monophonic pitch estimation, and why it handles low hummed notes better than an FFT.

The pipeline

  1. Decode — the audio file is decoded with the Web Audio API into a raw sample buffer.
  2. Frame — the buffer is split into overlapping windows (1024 samples with a 512-sample hop).
  3. Detect — YIN returns a frequency for each frame, or nothing if the frame is silent or unpitched.
  4. Segment — consecutive frames with the same MIDI note are merged into a single note; notes shorter than the minimum duration are discarded.
  5. Quantise — note start times are snapped to the chosen grid at the chosen tempo.
  6. Write — the notes are encoded as MIDI note-on and note-off events inside a Standard MIDI File.

What the MIDI file contains

The generated file is a Format 0 Standard MIDI File — a single track containing a tempo meta event and then the note events. It follows the published specification: an MThd header chunk with the format, track count, and division (ticks per beat), followed by an MTrk track chunk containing variable-length delta times and MIDI channel messages.

Getting a clean result

  • Use a clear, steady pitch. Humming works better than singing lyrics, because consonants break the periodic signal.
  • Keep it short. Five to thirty seconds of melody is the sweet spot. Longer recordings take longer to analyse and tend to accumulate errors.
  • Avoid background noise. A fan, a TV, or traffic adds frequencies that confuse the detector.
  • Leave a little silence between notes. The segmentation relies on pitch changes; blurring notes together makes the boundaries ambiguous.
  • Adjust sensitivity if needed. If the tool is missing quiet notes, raise it slightly. If it is inventing notes in silence, lower it.

Limitations — read before relying on the output

  • Monophonic only. A chord, a full mix, or overlapping voices will return the strongest pitch, not a transcription. This is a limitation of the algorithm, not a bug.
  • Pitch detection is an estimate. Background noise, vibrato, and breathy singing can cause octave errors or missed notes. Review the piano roll before using the result.
  • Rhythm is quantised, not transcribed. The tool snaps note starts to a grid. It does not detect swing, rubato, or expressive timing.
  • No velocity, articulation, or instrument. Every note is written at a fixed velocity on the default MIDI channel. The point is to capture the melody, not the performance.
  • Long or noisy files will be slow and less accurate. The analysis runs in the browser and is O(n²) per frame; a 30-second clip is a reasonable upper bound.
  • Browser support. Requires Web Audio API and decodeAudioData, which are available in all modern browsers. Microphone recording requires HTTPS or localhost.

Frequently asked questions

How do I convert audio to MIDI?

Upload a hummed or whistled recording, or record one directly in the tool. Click Analyze audio. The tool detects the pitch over time, groups it into notes, and generates a Standard MIDI File you can download and open in any DAW.

Does this work for full songs or chords?

No. It is designed for monophonic sources — one melody at a time. Polyphonic transcription, which separates a chord or a full mix into individual notes, is a different and much harder problem. The tool will return the strongest pitch in a chord rather than all of them.

Is my audio uploaded to a server?

No. The file is decoded and analysed entirely in your browser using the Web Audio API. Nothing is sent anywhere, and the tool works offline after the page loads.

Why does it use YIN instead of FFT?

FFT has a fixed frequency resolution that is too coarse for low notes. YIN works in the time domain and uses parabolic interpolation to achieve sub-sample resolution, which makes it more accurate for hummed melodies and low pitches.

What format is the downloaded file?

A Standard MIDI File (`.mid`), Format 0, with 480 ticks per beat. It contains a tempo event and note on/off events, and opens in Ableton, Logic, FL Studio, GarageBand, Reaper, and any other DAW.

Why are some notes missing or wrong?

Pitch detection depends on a clean periodic signal. Background noise, breathy singing, vibrato, and notes that blur together can cause missed or incorrect notes. Try raising the sensitivity, shortening the recording, or humming more steadily.

Can I record directly in the browser?

Yes. Switch to the Record tab and click Start recording. The microphone is used locally, and the recording is analysed in the same way as an uploaded file. Microphone access requires HTTPS or localhost.

Does it detect rhythm and timing?

It detects note start times from the pitch changes, then snaps them to the quantisation grid you select. It does not detect swing, rubato, or expressive timing — those are deliberately discarded so the output aligns to a DAW grid.

Is my data stored anywhere?

No. The audio and the generated notes exist only in the page’s memory for the current session. Nothing is written to localStorage, cookies, or a server.
