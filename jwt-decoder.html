What is a JWT?

    

      A JSON Web Token (JWT) is a compact token format that can carry claims between
      systems. A common signed JWT has three dot-separated parts: a Base64URL-encoded
      header, a Base64URL-encoded payload, and a signature segment. The standard format
      and registered claims are described in
      RFC 7519.
    


    
What is the difference between decoding and verifying?

    

      Decoding makes the header and payload readable. Signature verification is a
      cryptographic operation that checks a signature using the appropriate key and
      algorithm. These are different tasks: a token can decode successfully and still
      have an invalid signature or contain untrusted claims.

Why check token expiration?

    

      When debugging an API authentication issue, the exp, nbf
      and iat claims can help identify a time-related problem. The page
      converts recognized numeric timestamps into readable local dates. It cannot account
      for every server-side clock, policy or application-specific requirement.
    


    
Privacy and token safety

    

      This page parses the token within your browser and does not send it to a decoding
      endpoint. However, browser extensions, compromised web code, shared-device history
      and copied credentials can still create risk. The safer approach is to use synthetic
      or short-lived test credentials whenever possible and not paste sensitive production
      tokens into tools you do not trust.
    

  


  

    
Frequently asked questions


    

      Does this JWT decoder verify the signature?
      

        No. It only decodes readable token data and inspects selected claims.
        It does not verify HMAC, RSA, ECDSA or any other signature.
      

    


    

      Can anyone read the contents of a JWT?
      

        The header and payload of a common signed JWT are Base64URL-encoded, not encrypted.
        Anyone with the token can usually decode those parts. Encrypted JWTs use a different
        structure and require the right decryption key.
      

    


    

      Why does the tool say my token has expired?
      

        If the payload includes a numeric exp claim earlier than the current
        device time, the tool marks that timestamp as past. This does not independently
        verify the token or establish that a server will reject it.
      

    


    

      What if the token has five parts?
      

        A five-part compact token commonly represents encrypted JWT content. This page does
        not decrypt JWE tokens; decryption requires the appropriate cryptographic material.
      

    


    

      Are my tokens uploaded?
      

        The decoding logic runs locally in your browser and makes no token-decoding request
        to this website. For sensitive credentials, use trusted code and test tokens whenever
        possible.
      

    


    

      Does a successful decode mean the token is valid?
      

        No. Successful decoding only means the selected parts could be parsed. Trust requires
        your application to verify the signature, expected issuer and audience, time claims,
        and any application-specific authorization rules.
