Inference notes

    What does a JSON to TypeScript converter do?

    JSON is a data format; TypeScript adds static types to JavaScript development. A JSON to TypeScript converter examines a JSON sample and generates type definitions that describe the observed values. These definitions can make API responses easier to work with in an editor and help a type checker catch mistakes in application code.

    How JSON values map to TypeScript

    • JSON strings: usually become string.
    • Numbers: become number; ordinary JSON does not distinguish integers from decimals in the same way.
    • Booleans: become boolean.
    • Objects: become named interfaces or type aliases.
    • Arrays: become array types, potentially containing unions.
    • Nulls: are represented as null when observed alongside other values.

    Why use multiple representative records?

    A single JSON object only shows the fields present in that example. It cannot tell whether a missing property is optional in the actual API. An array with several object examples can reveal when a key appears in some records but not others, allowing the generator to suggest optional properties.

    Null is not the same as optional

    A property such as nickname: null indicates an observed null value. An omitted nickname property indicates that the key was absent in that sample. A real API may permit both states, so you might need nickname?: string | null after reviewing the API contract.

    Why empty arrays need review

    From an empty array alone, a converter cannot infer the intended element type. This generator uses unknown[] rather than guessing whether the elements should be strings, numbers or objects.

    Important limitation: types are not runtime validation

    Generated TypeScript describes the shape your code expects. TypeScript's type information is erased when compiled to JavaScript, so generated interfaces do not automatically validate data received from an API at runtime. For untrusted data, use a runtime validation strategy in addition to static types.

    Recommended workflow: paste a representative API response, generate the initial types, review optional and nullable properties, adjust domain-specific types, then type-check the result in your own TypeScript project.

    Frequently asked questions

    How do I convert JSON to TypeScript?

    Paste or upload JSON, choose a root type name and output style, then select Generate TypeScript. Review the inferred properties before copying or downloading the code.

    Does it support nested JSON objects?

    Yes. Nested objects become separate named declarations, and parent declarations refer to those generated types.

    How are optional properties inferred?

    In inference mode, if several objects are observed for a type and a key is absent from some of them, that property is marked optional. A single object does not provide enough evidence to identify potentially optional fields.

    What happens when a value is null?

    When a field contains both null and a non-null value, the generator emits a union including null. If all observations are null, it uses unknown because the non-null type cannot be inferred from that sample.

    Can it generate TypeScript from a JSON array?

    Yes. It infers a root array type and combines the observed element types. Arrays of objects are analyzed together to find properties that are absent from some records.

    Does this tool send my JSON to a server?

    No JSON upload endpoint is used by this page. Parsing and generation run in your browser, without an external conversion library.

    Will generated types validate API responses at runtime?

    No. Type definitions help TypeScript check code during development, but they do not automatically verify incoming values at runtime. Add runtime validation where your application needs it.
