What is Base64?

Base64 is a binary-to-text encoding that turns any sequence of bytes into a string of printable ASCII characters — A–Z, a–z, 0–9, +, /, and padding =. It is used everywhere binary data has to travel through text-only channels: email attachments (MIME), JSON payloads, data URLs in CSS and HTML, JWTs, and API request bodies.

The trade-off is size: Base64 output is about 33% larger than the input bytes. It is not encryption and does not hide data — it is simply a safe way to move bytes through systems that expect text.

What does “decimal” mean in “Base64 to decimal”?

This is where most tools are ambiguous. A Base64 string encodes a sequence of bytes, and there are two different ways to express that sequence in decimal:

1. Byte array (0–255)

Each decoded byte becomes a decimal number between 0 and 255. The string SGk= decodes to two bytes, 72 and 105, so the byte array is [72, 105]. This is the right form for embedded code (Arduino, ESP32), byte-level protocols, and any situation where you need the individual byte values.

2. Big integer

The entire byte sequence is read as a single unsigned big-endian number. The same SGk= becomes the integer 18537 (because 72 × 256 + 105 = 18537, which is 0x4869 in hexadecimal). This is the right form for cryptographic and mathematical contexts, and for certain encoding schemes that treat the whole payload as one number.

Both answers are correct — they just answer different questions. This tool shows both side by side so you can pick the one you actually need.

How to use this converter

  1. Paste a Base64 string into the input box.
  2. The results update automatically — no button to click.
  3. Read the byte array, the big integer, and the decoded text.
  4. Use each card’s Copy button to grab the value you need.

Examples

  • SGVsbG8= → bytes [72, 101, 108, 108, 111], integer 310939249775, text Hello
  • SGk= → bytes [72, 105], integer 18537, text Hi
  • AAECAw== → bytes [0, 1, 2, 3], integer 66051 (no readable text)

Supported input formats

  • Standard Base64 — the usual + and / alphabet.
  • URL-safe Base64 — with - and _ instead of + and /; handled automatically.
  • Unpadded input — padding is added internally when the length is valid.
  • Whitespace — spaces, tabs, and line breaks are stripped before decoding.

Privacy and limitations

  • All conversion happens locally in your browser. Nothing is uploaded, logged, or sent anywhere.
  • This tool is a converter, not a decoder for encrypted content. Base64 is not encryption.
  • Very large inputs (over ~100 KB after decoding) are refused to prevent the browser from freezing. Use a command-line tool for larger files.
  • The big-integer output is displayed with a preview for very long numbers; the Copy button always copies the full value.
  • The decoded-text output only shows clean, printable UTF-8. Binary or control characters are reported instead of being dumped into the page.

Frequently asked questions

What is the difference between the byte array and the big integer?

The byte array shows each decoded byte as a separate decimal number from 0 to 255. The big integer reads the whole byte sequence as a single unsigned number, using the first byte as the most significant. For SGk=, the byte array is [72, 105] and the big integer is 18537.

Is my Base64 string uploaded to a server?

No. The conversion happens entirely in your browser using JavaScript. Nothing is sent anywhere.

Does this tool work with URL-safe Base64?

Yes. URL-safe Base64 uses - and _ instead of + and /. The tool detects and converts these automatically.

Why does the tool say my Base64 is invalid?

The most common reasons are: characters outside the Base64 alphabet, a length that cannot be decoded (a remainder of 1 after removing whitespace), or corrupted padding. The status line tells you which check failed.

Why is the big integer output so long?

Every 3 bytes become about 7 digits in decimal. A 100-byte input produces a big integer with roughly 240 digits. That is expected — for short inputs the integer is short, and for longer inputs the byte array is usually the more useful answer.

Can I convert decimal back to Base64?

This page converts Base64 to decimal. For the reverse direction, you can use the byte array with any standard Base64 encoder, or open a dedicated decimal-to-Base64 tool.

Does this tool decode encrypted data?

No. Base64 is an encoding, not encryption. If a string is encrypted and then Base64-encoded, this tool will only undo the Base64 layer — the result will still be encrypted.
