How to create a robots.txt file

A robots.txt file is a plain-text file that gives compliant crawlers instructions about which URL paths they may access. It is commonly used to manage crawling of a website and to point crawlers toward one or more sitemap files. The file is normally served at the website's root URL, such as https://example.com/robots.txt.

Robots.txt syntax example

A rule applies to the crawler user-agent group above it. For example, the following file allows the public site to be crawled while disallowing a particular path prefix. 

User-agent: *
Allow: /
Disallow: /private/

Sitemap: https://example.com/sitemap.xml

Always replace the example sitemap URL with the actual published sitemap for your own site. If a path pattern ends in a slash, that slash matters: /private/ is not identical to /private.

Understanding Allow and Disallow rules

Disallow

A Disallow rule requests that compliant crawlers not fetch matching paths. For example, Disallow: /search/ applies to paths beginning with /search/. An empty Disallow value does not block a path.

Allow

An Allow rule explicitly permits matching paths. It is often used as a more-specific exception to a broader Disallow rule.

Most-specific matching rule

If multiple rules match, compliant implementations generally use the most specific match. Under the standard, a matching Allow rule is preferred when Allow and Disallow rules have equivalent specificity. This tool's URL tester demonstrates common wildcard and end-anchor matching behavior; individual crawlers may have implementation-specific differences.

Wildcards and end anchors

Some major crawlers support * to match a sequence of characters and a trailing $ to mark the end of a path pattern. For example, Disallow: /*.pdf$ can match URLs whose paths end in .pdf under the supporting crawler's matching rules.

What are robots.txt user-agent groups?

A user-agent group begins with one or more User-agent lines followed by applicable rules. The wildcard * is used as a general group for crawlers without a more-specific matching group. Use individual groups when you need different policies for particular crawler products.

Crawler product tokens and their behavior can change over time. This generator intentionally allows custom user-agent tokens so the file does not depend on a hard-coded list of crawlers.

Adding a sitemap to robots.txt

A Sitemap directive points crawlers to a sitemap or sitemap index. Use a fully qualified HTTP or HTTPS URL that identifies a real, accessible sitemap file. You can provide more than one Sitemap directive when your site has multiple sitemap files or an index.

Adding the directive does not create the sitemap itself and does not guarantee that a crawler will fetch, index, or rank its URLs. Keep the sitemap contents, canonical URLs, and robots rules consistent.

What robots.txt cannot do

It does not secure private files

Robots.txt is not access control. Its contents are publicly accessible, and disallowed paths can still be discovered through links or other sources. Protect private data with authentication, authorization, and appropriate server-side controls.

It does not guarantee de-indexing

A disallowed URL can sometimes appear in search results even when its content cannot be crawled. If your goal is to prevent a page from appearing in search, use the appropriate indexing controls, removal methods, or access restrictions rather than treating robots.txt as a noindex directive.

It cannot force every crawler to comply

The file provides instructions to crawlers that choose to honor them. It cannot prevent all bots, scrapers, or other clients from requesting a public URL.

Where should you upload robots.txt?

  1. Save the downloaded file with the exact lowercase filename robots.txt.
  2. Place it at the root of the intended host, not inside a normal subfolder.
  3. Open the public URL, for example https://example.com/robots.txt, to verify it is served correctly.
  4. Test important allowed and disallowed paths using your search engine's current tools where available.
  5. Keep a backup of the previous file so you can restore it if a new rule blocks important crawling.

A domain and its subdomains can have separate robots.txt files. Make sure you deploy the file on the exact hostname whose crawling behavior you want to manage.

Frequently asked questions

What is a robots.txt file?

Robots.txt is a plain-text file used to give compliant web crawlers instructions about which paths they may access. It is generally published at the root of a website.

Is this robots.txt generator free?

Yes. You can generate, validate, test, copy, and download robots.txt rules on this page without creating an account or paying a tool usage fee.

Where does robots.txt need to be uploaded?

It normally belongs at the root of the relevant hostname, such as https://example.com/robots.txt. A file placed in a subfolder does not control the whole host.

What is the difference between Allow and Disallow?

Disallow requests that matching paths not be crawled. Allow explicitly permits matching paths and can act as a more-specific exception to a broader Disallow rule.

Can robots.txt hide pages from Google?

It is not a reliable way to prevent indexing. A URL may still appear in search results without its content if it is blocked from crawling but discovered elsewhere. Use suitable noindex or access-control methods when your goal is to prevent indexing or access.

Does robots.txt protect private information?

No. Anyone can request a publicly accessible robots.txt file, and compliant crawlers are only being asked to follow its instructions. Protect private information with authentication, authorization, and server-side access controls.

Can I add more than one sitemap?

Yes. Add each absolute sitemap URL on a separate line. A Sitemap directive identifies a sitemap location; the generator does not check whether that file exists or contains valid URLs.

Can I create separate rules for Googlebot and Bingbot?

Yes. Add separate user-agent groups with the product tokens you need and place the appropriate Allow or Disallow rules inside each group. Check the crawler's own documentation if you rely on crawler-specific behavior.

Does this tool test a live website?

The built-in tester simulates common robots.txt path-matching behavior using the generated or pasted rules. It does not fetch your site's live robots.txt or guarantee an exact match with every crawler implementation.

What happens if I block the entire website?

A broad Disallow rule can prevent compliant crawlers from fetching all paths in the matching group. Review the output carefully and verify important pages remain crawlable before deploying the file.
