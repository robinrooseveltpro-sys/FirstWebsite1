Why extract emails from text?

Copying addresses out of a document by hand is slow and error-prone. It is also the most common reason people reach for an extractor: a spreadsheet export, an email thread, a scraped page, or a PDF that has been converted to text, and somewhere inside it are the contacts they actually need.

The regex for an email address is simple enough to write by hand, but real text is messy. Addresses appear inside quotes, followed by punctuation, split across lines, or written with “at” and “dot” to dodge scrapers. This tool handles the common cases — standard name@domain.tld addresses, including + tags and multi-level domains — and strips the trailing punctuation that a naive matcher would leave attached.

How the extraction works

Each category uses a regular expression tuned to that data type, run against the full text in JavaScript. Matches are then normalised — emails are lowercased for deduplication, URLs have trailing punctuation trimmed, phone numbers are preserved as written — and stored in a set so duplicates collapse.

The patterns are deliberately permissive rather than strict. A strict email regex will reject valid addresses like first.last+tag@sub.example.co.uk; a permissive one accepts them and lets you review the list. That is the right trade-off for this task: false positives are visible and easy to delete, false negatives are invisible and cost you contacts.

The regex patterns, in plain terms

  • Email: [A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,} — the standard pattern, case-insensitive, with a boundary check to avoid matching inside a URL path.
  • URL: https?://… and www\.… with a TLD check, plus a trailing-punctuation trim so a link at the end of a sentence does not capture the period.
  • Phone: a permissive pattern requiring at least seven digits, allowing +, spaces, dashes, dots, and parentheses, with optional country code.
  • IPv4: four groups of 1–3 digits, each validated to 0–255, with an optional :port.
  • Date: four common formats — ISO, US slash, European dash, and spelled-month — matched separately and reported as written.
  • Hashtag: # followed by letters, digits, or underscores, not preceded by a word character.
  • Mention: @ followed by letters, digits, underscores, or dots, not preceded by a word character — which is why it does not match the @ inside an email.

Limitations — read before relying on the output

  • This is a pattern-matching tool, not a parser. It does not validate that an email address actually exists, that a URL resolves, or that a phone number is in service.
  • Addresses written to evade scrapers — “name at domain dot com” — will not be extracted. That is deliberate: matching them reliably would require a language model, not a regex.
  • Very short or ambiguous digit strings can be matched as phone numbers when they are not. Review the phone list before using it for outreach.
  • The URL matcher accepts bare domains with common TLDs, which means a sentence ending in a file extension like report.pdf can occasionally be captured. Review the URL list.
  • Dates are reported as written and are not normalised to a single format. A 03/04/2026 match is ambiguous between US and European order and is left as-is.
  • The tool processes text in memory in the browser. Extremely large inputs (hundreds of thousands of characters) may be slow on low-end devices; the character counter shows the current size.
  • This tool does not bypass any website’s terms of service. Use it on text you have the right to process.

Privacy: why this runs in the browser

Text you paste into an online tool can contain client names, personal email addresses, internal URLs, or credentials. Uploading that to a server is a privacy decision, and for many people it is the wrong one.

This tool never sends the text anywhere. The extraction is pure JavaScript running in the page, so it works with the network disconnected after the page loads. You can verify that in your browser’s network tab: there is no request carrying your input.

Frequently asked questions

How do I extract emails from text?

Paste the text into the box above. The email extractor runs automatically and lists every address it finds, deduplicated and lowercased. Click the Emails tab to see the list, then use Copy list or Download .txt to take it with you.

Does this tool upload my text to a server?

No. Everything runs in your browser. The text is never sent anywhere, and the tool keeps working if you disconnect from the network after the page loads.

Can it extract phone numbers in international format?

Yes. The phone matcher accepts a leading + and country code, and allows spaces, dashes, dots, and parentheses as separators. It requires at least seven digits, which is why it does not match short numbers like ZIP codes.

Why does the mention extractor not match the @ in an email address?

The mention pattern requires that the @ is not preceded by a word character. In an email like name@domain.com, the @ follows a letter, so it is skipped. In a tweet like “thanks @examplehq”, the @ follows a space, so it matches.

Does it remove duplicates?

Yes. Each category is deduplicated. Emails are lowercased before comparison, so Name@Example.com and name@example.com count once. URLs have trailing punctuation trimmed before comparison.

What is the mailto: button for?

It builds a mailto: link with all extracted emails in the To field, so you can open your email client with the recipients already populated. It is useful for a small batch; for large lists, use the CSV-friendly copy or download instead.

Can I extract data from a PDF or an image?

This tool accepts text, not PDF or image files. Convert a PDF to text first, or use an OCR tool to extract text from an image, then paste the result here.

Does it work offline?

Yes, once the page has loaded. The extraction logic is entirely client-side, so it continues to work without a network connection.

Is my data stored anywhere?

No. The tool does not write your input to localStorage, cookies, or any server. It exists only in the page’s memory for the current session.
