Why paste text instead of using a spreadsheet

If you have ever copied a block of messy text into a spreadsheet hoping Excel would find the emails, you already know why this exists. Excel does not see an email. It sees a string. You end up writing a regular expression in a cell, or splitting by at signs and commas, and it works fine until the text has an email with a plus sign or a domain with two dots in it. Then you are debugging a formula at 11pm.

Copying text into a tool that already understands the patterns is faster. It also handles the edge cases that trip up spreadsheet formulas. Addresses like john.smith+newsletters@example.co.uk come out in one piece. Phone numbers formatted as (202) 555-0180, 202-555-0180, and +1 202 555 0180 all get normalized. IPv4 addresses do not get mangled into phone numbers.

What the extraction actually catches

Emails. Standard pattern: local part, at sign, domain, dot, top-level domain. Local parts can include dots, plus signs, underscores, and hyphens. Domains can have subdomains. The top-level domain has to be at least two letters, so test@example.c will not match. test@example.co will.

URLs. Anything starting with http://, https://, or www.. Trailing punctuation is stripped so a URL at the end of a sentence does not include the period.

Phone numbers. US format in the common layouts: with parens, with dots, with dashes, with spaces, with or without the +1 country code. Ten digits in 3-3-4 grouping. International numbers work if they start with a plus and a country code, because the plus is a clear signal.

IPv4 addresses. Four octets, each 0 to 255, separated by dots. Extracted before phone numbers so a server log line does not produce five false phone matches.

The validation pass, and what gets flagged

The extractor grabs anything that looks like an email. Then a separate check runs on each one. Not to remove it, but to flag it if something is off. The pattern is broad enough to catch malformed addresses; the validation is narrow enough to notice when they are malformed.

An address gets flagged when the domain has no dot, when it ends with a dot, when it has two dots in a row, when the local part is over 64 characters, when the whole address is over 254 characters, or when the top-level domain is shorter than two letters. These are not absolute rules. Some intranet systems use addresses without a top-level domain, for example. But for 99 percent of cases, a flagged address is one you want to look at before you use it.

What the tool does not do. It does not verify that an email address actually exists. That requires a network lookup and a live mail server, which this tool deliberately does not do because it would break the privacy guarantee. It checks the format. Whether the mailbox is real is a different question.

What deduplication means here

If john@example.com appears four times in your text, you get it once. Emails and URLs are compared case-insensitively, so JOHN@EXAMPLE.COM and john@example.com count as duplicates. Phone numbers are compared by digits only, so (202) 555-0180 and 202-555-0180 count as the same number.

What you see in the results is the first occurrence as written in your text. So if the first mention used the parenthesized format, that is the format shown. This matters for email lists where you want to preserve the display format.

Common places people use this

Recruiters and sales teams. A pasted block of LinkedIn profile text often hides three or four addresses in the body. Instead of reading every line, paste the whole block and copy the list. The privacy guarantee matters most here, because profile text often contains personal information that should not leave the browser.

Developers parsing logs. Log files contain emails, IPs, URLs, and phone numbers mixed with timestamps and stack traces. Extracting the IPs is usually the goal, but once you are in the tool you will often want the URLs too. Running both at once saves pasting twice.

Freelancers cleaning client notes. Meeting notes and email threads have phone numbers buried mid-paragraph. The tool pulls them out without disturbing the surrounding text, which matters if you want to keep the notes intact for reference.

Anyone who received a shared document. PDFs converted to text often lose their formatting. Emails that were hyperlinks become plain strings. The extractor does not care about formatting. It finds the patterns regardless.

Basics

What happens to my text when I paste it here?

Nothing. The text stays in your browser. It is not sent to a server, not stored in local storage, not logged anywhere. When you close the tab, the text is gone. This is a deliberate design choice, because the tool often processes text that contains personal contact information.

How large a block of text can I paste?

There is no hard limit in the tool itself. Practical limits are your browser's memory and your patience. Blocks of 100,000 characters work fine. Blocks of 2 million characters will work but may feel sluggish while typing.

Does it work on mobile?

Yes. The layout stacks vertically on narrow screens. Pasting from the clipboard works on iOS Safari and Android Chrome, though some mobile browsers restrict clipboard reads without a user gesture. If the paste button does not work, tap the textarea and use your device's built-in paste gesture.

Why do I need to press extract when other tools are automatic?

There is a debounce that runs extraction automatically a moment after you stop typing, so pressing the button is rarely necessary. The button exists because some people paste a large block and want to know exactly when extraction starts, or want to re-run after a filter change. It is a control, not a requirement.

What gets found

Will it find emails with plus signs or dots in the local part?

Yes. The pattern supports +, ., _, and - in the local part, which covers every practical email address format in use. Addresses like sarah.chen+newsletter@example.co.uk come out in one piece.

Why did it find a URL that is only part of the real one?

Some URLs have characters that are valid in a URL but ambiguous in prose, like trailing periods or closing parens after a link. The extractor strips trailing punctuation to avoid including sentence-ending periods, which means a URL ending in an unusual punctuation character might get cut short. This is rare in practice. If it happens, the URL in the results is still the working base of the address.

Why does the phone extraction sometimes pick up a date or ZIP code?

Phone numbers and other numeric strings share structure. A string like 20005-1234 looks like a phone number to a regex because it has the right digit counts separated by a hyphen. In practice, if your text has ZIP+4 codes and phone numbers mixed, a few false positives will slip through. Delete them from the results after copying, or paste ZIP codes into a separate block.

Does it find international phone numbers?

Reliably, only when they start with a plus and a country code. A UK number written as 020 7946 0958 without the +44 prefix will not match, because the extractor's phone pattern is built around US groupings and international numbers that signal themselves with a plus. If you need to extract international numbers written in their local format, the US-focused pattern will miss them.

Validation

What does "flagged" mean on an email?

The extractor found an address but the format check noticed something unusual. Common reasons include a domain with no top-level extension like support@internal, two dots in a row, or an overlong local part. The address still appears in the results. The flag just tells you to look at it before you use it in a mailing list.

Does the tool check if an email actually exists?

No. Verifying that an address has a working mailbox requires a network request to a mail server, which this tool does not do because it would break the privacy guarantee. Format validation is local. Deliverability is a different question and requires a different tool.

Can I turn off the flagging?

Not currently. The flag is informational and does not remove anything from the results, so if you do not want it, ignore the badge and copy the address. If the flagging becomes annoying on a specific batch of text, paste the addresses one per line into a text editor and clean them there.

Privacy

Why does the privacy guarantee matter here specifically?

Because the text people paste into an email extractor almost always contains personal information. Names, addresses, phone numbers, email addresses tied to specific people. If the tool uploaded that text to a server to do the extraction, the operator of that server would have a database of personal contact information. This tool does the extraction in the browser, so the text never leaves the device.

Does the tool use analytics or third-party scripts?

The page loads no external scripts beyond the tool's own code. There is no Google Analytics, no tracking pixel, no font CDN, no third-party library. Ad slots are marked in the source but the ad code itself, if you add it, is the only external dependency. If ad scripts are added, they may set cookies, which is a separate concern from whether the text you paste is uploaded.

Can I verify the tool does not upload anything?

Yes. Open the browser's developer tools, go to the Network tab, clear the log, then paste text and press Extract. If the tool uploaded the text, you would see a network request. You will not see one, because there is no code that makes one. This is the kind of claim that is worth verifying rather than trusting.

Export

What does the CSV look like?

Three columns: type, value, and flag. Type is one of email, url, phone, or ip. Value is the extracted string. Flag is empty for clean results and contains the validation reason for flagged emails. This format imports into Excel, Google Sheets, and every CRM without adjustment.

Can I copy just one type?

Yes. Switch to that tab and use the "Copy tab" button. It copies only the currently filtered list, so if you have used the filter box to narrow down the results, only the visible items get copied. This is useful when you want the emails but not the phone numbers from a mixed block.

Does "Copy all" include everything or just the current tab?

"Copy all" copies every result from every type, grouped by type with a header line for each. So the copied text will show "Emails" then a blank line then the email list, then "URLs" and so on. This is useful when you want a single clipboard payload that documents what was extracted.

Why does the download give a .csv instead of .txt?

Because CSVs open directly in spreadsheet apps with the type column preserved. A text file would work too, but the CSV format is more useful when you are about to sort or filter the results. The file is a plain UTF-8 CSV, so if you would rather have a text file, rename the download from .csv to .txt after it saves.
